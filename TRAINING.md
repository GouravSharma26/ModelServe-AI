# Training and evaluation

## Dataset

Release A uses IBM's public [Telco Customer Churn sample](https://github.com/IBM/telco-customer-churn-on-icp4d/blob/master/data/Telco-Customer-Churn.csv). The source repository contains the [Apache License 2.0](https://github.com/IBM/telco-customer-churn-on-icp4d/blob/master/LICENSE). IBM describes the sample as fictional telecommunications data. This implementation validates the source's 21 columns (20 inputs and target `Churn`), target labels, numeric types, and required values. Blank `TotalCharges` values are allowed and imputed from training data.

The loader downloads the raw CSV from IBM's repository if `--data` is omitted. A local `Telco-Customer-Churn.csv` can be supplied instead. Data files and generated model binaries are ignored by Git. Tests use synthetic fixtures and do not contact the public source.

`customerID` is excluded because it is an identifier. Four numeric inputs use training-set median imputation and standardization; categorical inputs use training-set most-frequent imputation and one-hot encoding. Unseen categories are ignored by the encoder.

## Environment

The supported interpreter is CPython 3.12. Dependencies are pinned in `requirements.lock`. The recorded training run used Python 3.12.6, NumPy 2.1.3, Pandas 2.3.2, SciPy 1.16.2, and scikit-learn 1.5.2.

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.lock
python -m pip install --no-deps -e .
```

## Run training

```powershell
modelserve-train --output artifacts/models
# Or with a local copy:
modelserve-train --data data/raw/Telco-Customer-Churn.csv --output artifacts/models
```

The split is stratified with seed 42: 60% training, 20% validation, and 20% test. A prior-probability dummy baseline and two fixed candidates (class-weighted logistic regression and random forest) use the same split. Selection uses validation average precision, with validation F1 as tie-breaker. The selected candidate is evaluated once on the held-out test set. The decision threshold remains 0.5 and is not tuned on the test set.

The command creates a new timestamped version directory under the output directory, then writes `model.joblib`, `manifest.json`, and `evaluation.json`. Existing model versions are not overwritten. The manifest records source and data fingerprints, feature schema, excluded columns, split policy, package versions, validation results, selected model, held-out test metrics, and artifact SHA-256. Joblib artifacts can execute code when loaded: only artifacts produced by this training command are trusted. The checksum is an integrity check, not proof that an arbitrary artifact is safe.

Metrics include precision, recall, F1, ROC-AUC, average precision (PR-AUC summary), and confusion matrix. Scores are uncalibrated probability estimates. Only values generated by a real dataset run belong in the model card.

## Reproducibility limits

The fixed split seed and pinned environment make the workflow repeatable for an unchanged source file and compatible runtime. The artifact version embeds the creation time, so checksums are not expected to match across separate runs. A random stratified split does not establish generalization to future customers or production populations.
